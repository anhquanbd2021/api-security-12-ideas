API Security Guide

Twelve controls for securing an API boundary. Explore what each control protects, how it fails, what to implement, and where this Express and NestJS lab makes the behavior visible.

Educational simulator. Public tokens and in-memory services model behavior; they are not production identity, storage, TLS, or payment systems.

Control 01 · Identity

Authentication

Proves who calls the API before protected work begins.

Threat
Missing, stolen, expired, or revoked credentials let an attacker impersonate a caller.
Mitigation
Validate tokens server-side, enforce expiry and revocation, rotate credentials, and never place tokens in URLs.
In this lab
Bearer tokens resolve through an asynchronous identity provider. Missing and expired tokens return 401.
401Bearer token

Control 02 · Identity

Authorization

Decides which actions and resources an authenticated caller may access.

Threat
Broken object-level authorization exposes another user's records when IDs are changed.
Mitigation
Check action and resource ownership on every request. Derive authority from trusted server state, not request fields or hidden UI.
In this lab
The repository enforces ownership. Alice requesting Bob's document gets 404, limiting resource enumeration.
BOLA404
Try authorization failure
Control 03 · Resilience

Rate Limiting

Caps request volume by identity, source, endpoint, or business operation.

Threat
Brute force, scraping, denial of service, and traffic spikes exhaust capacity or abuse sensitive flows.
Mitigation
Use atomic distributed counters, endpoint-aware limits, predictable 429 responses, and retry guidance.
In this lab
A Redis-like simulator atomically allows three requests per identity and returns Retry-After when exhausted.
429Retry-After
Send requests in the lab
Control 04 · Boundary

Input Validation

Rejects malformed, unexpected, oversized, or out-of-range input early.

Threat
Unchecked values reach SQL, shell commands, templates, file paths, or downstream systems.
Mitigation
Allow known types, lengths, formats, ranges, and values at every trust boundary. Keep parameterization and output encoding too.
In this lab
Document and payment fields are validated; malformed JSON returns 400 and payloads over 8 KiB return 413.
400413
Try invalid input
Control 05 · Data

Output Encoding

Prevents untrusted data from becoming executable content in its output context.

Threat
A value safe in JSON becomes dangerous in HTML, an attribute, JavaScript, CSS, or a URL.
Mitigation
Use context-aware escaping, avoid markup concatenation, set correct content types, and add CSP as defense in depth.
In this lab
Responses use JSON serialization and explicit content types. Static pages avoid inline scripts and run under a restrictive CSP.
CSPJSON
Inspect encoded output
Control 06 · Boundary

HTTPS Everywhere

Encrypts traffic and protects requests from network interception and tampering.

Threat
Plain HTTP exposes credentials and sensitive data to hostile networks, proxies, or compromised infrastructure.
Mitigation
Validate certificates, redirect HTTP, use modern TLS, secure cookies, HSTS where appropriate, and prevent mixed content.
In this lab
Render terminates public HTTPS. Localhost intentionally uses HTTP for development; production transport belongs at the deployment edge.
TLSHSTS
Open secure public lab
Control 07 · Operations

Secret Rotation

Limits damage when credentials or signing material become exposed.

Threat
Long-lived database passwords, API keys, signing keys, or cloud credentials remain useful after leakage.
Mitigation
Use a secret manager, least-privilege access, overlapping rotation windows, and immediate revocation for compromise.
In this lab
Fixed tokens are public test fixtures only. Production systems need managed secrets and real issuer key rotation.
RevocationKey lifecycle
Observe rejected token
Control 08 · Identity

Least Privilege

Gives each user and service only permissions required for its work.

Threat
A stolen account or vulnerable service gains a much larger blast radius than its job requires.
Mitigation
Scope user roles, service accounts, database grants, cloud policies, CI runners, and third-party integrations.
In this lab
Alice and Bob can retrieve only owned records. Admin-only failure simulation demonstrates a separate authority level.
RBACBlast radius

Control 09 · Resilience

Idempotency Keys

Stops supported retried operations from producing duplicate side effects.

Threat
A network failure hides a successful payment response, and retrying charges the customer twice.
Mitigation
Bind a unique key to request data, store the result atomically, return it on replay, and reject changed payloads.
In this lab
The same payment key and amount returns the original payment; key reuse with another amount returns 409.
Replay409
Try payment replay
Control 10 · Operations

Audit Logging

Records who did what, when, to which resource, and with what result.

Threat
Teams cannot investigate access, permission changes, exports, or administrative actions after an incident.
Mitigation
Capture actor, action, resource, timestamp, request ID, and result in protected append-only storage without secrets.
In this lab
Payment actions append redacted audit events correlated by request ID; simulator tests verify secret removal.
Request IDRedaction
Generate audit event
Control 11 · Operations

Dependency Scans

Finds known vulnerabilities in direct and transitive packages.

Threat
A vulnerable router, serializer, image library, or build tool exposes every service that loads it.
Mitigation
Lock versions, scan dependencies and artifacts, review exploitability, remove unused packages, and deploy updates.
In this lab
npm audit --audit-level=high gates high-severity findings while the lockfile makes resolution reproducible.
CVELockfile
Inspect locked dependencies
Control 12 · Boundary

Error Hygiene

Returns useful failures without revealing internals attackers can exploit.

Threat
Stack traces, paths, SQL, credentials, internal hosts, and framework details disclose attack paths.
Mitigation
Return stable status codes and safe messages with request IDs; retain detailed diagnostics only in protected logs.
In this lab
A simulated internal failure contains sensitive text internally but returns only 500, a generic message, and request ID.
